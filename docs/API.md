here# متطلبات الـ API

## 1) GGSoma Partner API

**الأساس**: `https://ggsoma.store/api/partner/v1`
**المصادقة**: `Authorization: Bearer sk_live_…` على كل نداء عدا `/health`

### المسارات المستعملة بالمشروع

| المسار | وين مستعمل | كل قديش |
|--------|------------|---------|
| `GET /health` | فحص الخدمة | عند الطلب |
| `GET /balance` | رصيدك عندهم | كل ساعة + لوحة التحكم |
| `GET /usage` | إحصائيات API | لوحة التحكم |
| `GET /catalog/providers` | المزوّدين | كل مزامنة |
| `GET /catalog/products` | المنتجات + المخزون + الأسعار | كل مزامنة |
| `GET /catalog/products/:ref` | وصف وتعليمات منتج | 15 منتج كل مزامنة (بالتناوب) |
| `POST /orders` | إنشاء الطلب | كل عملية شراء |
| `GET /orders?externalOrderId=` | البحث عن طلب عالق | المُصالح |
| `GET /orders/:orderCode` | جلب محتوى التسليم | المُصالح |

### الحدود

| الباقة | طلب/دقيقة | أمر شراء/دقيقة |
|--------|-----------|----------------|
| standard (افتراضي) | 60 | 10 |
| limited | 10 | 2 |
| premium | 300 | 50 |

الكتالوج المكاشّ بجدولك بيوفّر معظم الاستهلاك — تصفّح الزبون ما بيلمس الـ API إطلاقاً.

استهلاك الدورة الوحدة (كل ١٠ دقايق):
- نداءين للقوائم (`providers` + `products`)
- ١٥ نداء لتفاصيل المنتجات، بفاصل ١.١ ثانية بينهم

المجموع ~١٧ نداء موزّعين على ١٧ ثانية — بعيد عن حد الـ ٦٠/دقيقة.
والمُصالح بيباعد ١.٢ ثانية بين كل طلب.

### الـ idempotency — أهم شي بالتكامل

كل طلب بيروح مع `externalOrderId` فريد منّا (`ax-<tgId>-<time>-<rand>`).
نفس الـ id مرة تانية → نفس الطلب، **بدون خصم تاني**.
هاد يلي بيخلّي إعادة المحاولة بعد الـ timeout آمنة.

### تصنيف الأخطاء — كل الـ 17 كود من §14

| الصنف | الأكواد | HTTP | التصرّف |
|-------|---------|------|---------|
| **نهائي** | `OUT_OF_STOCK` `PRODUCT_NOT_FOUND` `PRODUCT_UNAVAILABLE` `PRODUCT_NOT_ALLOWED` `INVALID_QUANTITY` `VALIDATION_ERROR` `UNSUPPORTED_DELIVERY_TYPE` `ORDER_NOT_FOUND` | 400/404 | رجّع الرصيد فوراً |
| **حسابنا** | `INSUFFICIENT_BALANCE` `INVALID_API_KEY` `API_KEY_EXPIRED` `USER_BLOCKED` `API_ACCESS_DISABLED` `PARTNER_SUSPENDED` | 400/401/403 | رجّع الرصيد + نبّه الأدمن |
| **مؤقت** | `MAINTENANCE` `RATE_LIMIT_EXCEEDED` `NETWORK_ERROR` `BAD_RESPONSE` | 503/429/— | **لا ترجّع** — اترك PENDING للمُصالح |

**`FAILED` بينتصنّف حسب الـ HTTP** (موثّق بـ 400/500):
- `400` = فشل مؤكّد، ولا خصم صار → **نهائي**، رجّع الرصيد
- `500` = غامض، ممكن يكون نجح عندهم → **مؤقت**، خلّي المُصالح يحسمها

> الصف الثالث هو الفرق بين نظام سليم ونظام بينزف فلوس.

### ملاحظة على `/health` وقت الصيانة

المسارات المحمية بترجّع `{ ok:false, error:{ code:"MAINTENANCE", ... } }`.
بس `/health` بيرجّع **`error` كنص**: `{ ok:false, service:"partner-api", error:"maintenance" }`.

الشكلين مختلفين — العميل بيتعامل مع الاتنين. لو قرأت `error.code` على رد `/health` بترجعلك `undefined`.

### الحقول المستعملة من الكتالوج

| الحقل | الاستعمال عندك |
|-------|----------------|
| `yourPrice` | التكلفة — أساس حساب سعرك |
| `stock.count` / `stock.inStock` | لون الزر والعدد بين قوسين + كشف الزيادة |
| `stock.maxQuantity` | حدّ الكمية بالطلب |
| `durationDays` · `warranty.days` | صفحة المنتج |
| `deliveryType` | شكل عرض التسليم |
| `emoji.normal` / `emoji.customTelegramId` | إيموجي القوائم والأزرار |
| `sortOrder` | ترتيب العرض |
| `flags.hasInstructions` | هل نسحب التعليمات |
| `flags.sensitiveDelivery` | تعليم البيانات الحسّاسة |
| `description` + `descriptionFormat` | وصف المنتج (بعد تنظيف HTML) |
| `instructions` | بلوك «التعليمات المهمة» القابل للطي |
| `catalogPrice` | سعرهم المعلن — مرجع لك بلوحة التحكم، مو معروض للزبون |

### الحقول المستعملة من رد الطلب (§11)

| الحقل | الاستعمال |
|-------|-----------|
| `orderCode` | مرجع الطلب — بينعرض للزبون وبينحفظ |
| `externalOrderId` | معرّفنا — أساس الـ idempotency |
| `totalCharged` | التكلفة الفعلية — مقارنة الهامش |
| `unitPrice` | سعر الوحدة — بتنبيه الخسارة |
| `balanceAfter` | **رصيدنا عندهم بعد الشراء** — منراقبه بدون نداء `/balance` إضافي |
| `delivery.*` | محتوى التسليم |
| `lines[]` | تسليم الطلبات الجماعية (`quantity > 1`) |
| `product.name` / `product.slug` | بتنبيهات الأدمن |

> `balanceAfter` بيجي **بأول POST ناجح فقط** — بينحذف عند الإعادة (§11).
> فمنستعمله للتنبيه المبكّر، والمراقبة الدورية عبر `/balance` بتضل شغالة.

### أنواع التسليم

| النوع | الحقل | ملاحظة |
|-------|-------|--------|
| `LINK` | `delivery.link` | آمن للتمرير للزبون |
| `COUPON` | `delivery.code` | سلّمه مرة وحدة |
| `READY_ACCOUNT` | `delivery.content` | حسّاس — لا تسجّله بالـ logs |

الطلبات الجماعية (`quantity > 1`) بترجّع `lines[]` بدل `delivery`.

## 2) Telegram Bot API

**الحد الأدنى**: Bot API **9.4** (فبراير 2026) — للأزرار الملوّنة.
بدونه البوت بيشتغل عادي، بس الأزرار بتطلع بلون التطبيق الافتراضي.

### الميزات المستعملة

| الميزة | مضاف بـ | الاستعمال |
|--------|---------|-----------|
| `editMessageText` | قديم | التنقّل بدون رسائل جديدة |
| `<blockquote expandable>` | 7.x | بلوكات «ماذا ستحصل عليه» |
| `style` على الأزرار | 9.4 | `success` أخضر · `danger` أحمر · `primary` أزرق |
| `icon_custom_emoji_id` | 9.4 | إيموجي مخصص على الزر |
| `<tg-emoji>` | 9.4 للبوتات | إيموجي بريميوم بالنص |

### شرط الإيموجي المخصص

بيشتغل بس إذا:
- **صاحب البوت عنده Telegram Premium**، أو
- البوت عليه يوزرنيم مشترى من Fragment

بدون هالشرط الوسم بينتجاهل والمستخدم بيشوف الإيموجي البديل — **ما بينكسر شي**.
فعّله من ⚙️ لوحة التحكم → 🎨 المظهر → «إيموجي بريميوم».

### حدود الإرسال

تلغرام بيحدّ البث بحوالي **٣٠ رسالة/ثانية**.
دالة `broadcast()` بترسل بدفعات ٢٥ مع فاصل ثانية، وبتتجاهل من حظر البوت.

## 3) Supabase

بيتنادى عبر `@supabase/supabase-js` بمفتاح `service_role`.

### الدوال الذرّية — كل الأمان المالي

| الدالة | الوظيفة |
|--------|---------|
| `debit_and_open_order` | خصم + فتح طلب PENDING بعملية واحدة |
| `complete_order` | تثبيت + تحديث الإنفاق + عمولة الإحالة |
| `refund_order` | إرجاع idempotent — ما بيرجّع مرتين |
| `credit_user` | إيداع / تعديل رصيد |
| `redeem_voucher` | استعمال قسيمة ذرّي |
| `open_withdrawal` | حجز مبلغ السحب |
| `reject_withdrawal` | رفض + إرجاع |

> شرط `balance >= amount` موجود **جوّا الـ UPDATE** نفسه.
> بدونه، ضغطتين بنفس الثانية بتسحب أكتر من الرصيد.
