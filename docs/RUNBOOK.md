## المرحلة 1 — البوت

### 1.1 أنشئ البوت
[@BotFather](https://t.me/BotFather) → `/newbot` → اسم ويوزرنيم → **انسخ التوكن**.

### 1.2 اضبط شكله
```
/setuserpic       صورة مربعة 512×512
/setdescription   النص يلي بيظهر قبل ما يضغط «ابدأ»
/setabouttext     سطر قصير بملف البوت
```
> الأوامر وزر القائمة بينضبطوا تلقائياً من الكود.

### 1.3 خد معرّفك الرقمي
ابعت أي رسالة لـ [@userinfobot](https://t.me/userinfobot). الرقم اللي بيرجعلك هو `ADMIN_IDS`.

## المرحلة 2 — قاعدة البيانات

1. [supabase.com](https://supabase.com) → **New project** → اختر أقرب منطقة إلك
2. **SQL Editor** → شغّل الملفات **بهالترتيب حصراً**:

| # | الملف | بيعمل شو |
|---|-------|----------|
| 1 | `sql/01_schema.sql` | 13 جدول |
| 2 | `sql/02_functions.sql` | 8 دوال ذرّية |
| 3 | `sql/03_seed.sql` | 31 إعداد + النصوص + المستويات |

> رسائل `NOTICE: ... already exists, skipping` طبيعية لو أعدت التشغيل. الأخطاء الحقيقية بتبدأ بـ `ERROR`.

**للترقية لاحقاً:** أعد تشغيل الملفات التلاتة بنفس الترتيب. `01_schema.sql` فيه قسم `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` بيضيف الأعمدة الجديدة على جدولك الموجود، و`02_functions.sql` فيه `DROP` قبل الدوال يلي بتغيّر شكل مخرجاتها.

3. **Settings → API** → انسخ:
   - `Project URL` → `SUPABASE_URL`
   - `service_role` key → `SUPABASE_SERVICE_KEY`

> ⚠️ `service_role` بيتخطّى كل الصلاحيات. سيرفر فقط، ولا يُرفع على GitHub أبداً.

### تحقّق سريع
بالـ SQL Editor:
```sql
select count(*) from settings;   -- لازم 31
select routine_name from information_schema.routines where routine_schema='public';
```
لازم تشوف 8 دوال. لو أقل، أعد تشغيل `02_functions.sql`.

## المرحلة 5 — Render

### 5.1 أنشئ الخدمة
**New → Web Service** → اربط المستودع:

| الحقل | القيمة |
|-------|--------|
| Runtime | Node |
| Build Command | `npm ci` |
| Start Command | `npm start` |
| Health Check Path | `/health` |
| Plan | **Starter** (مدفوع) |

### 5.2 المتغيرات

**إلزامية:**
```
BOT_TOKEN               من BotFather
ADMIN_IDS               معرّفك الرقمي
WEBHOOK_SECRET          نص عشوائي طويل (Render بيولّده)
GG_BASE_URL             https://ggsoma.store/api/partner/v1
GG_API_KEY              sk_live_...
SUPABASE_URL            https://xxx.supabase.co
SUPABASE_SERVICE_KEY    eyJhbGci...
PORT                    3000
```

**لكريبتوموس فقط:**
```
CRYPTOMUS_MERCHANT_ID
CRYPTOMUS_API_KEY
CRYPTOMUS_PAYMENT_KEY   (اختياري — لو مفتاح الويبهوك مختلف)
```

> Binance Pay و Telegram Stars **ما بدهم ولا متغير بيئة**.

### 5.3 انشر، بعدين أضف الرابط
1. **Deploy** → استنى ينجح
2. انسخ رابط الخدمة → أضف `WEBHOOK_URL` = `https://xxx.onrender.com`
   **بدون `/` بالآخر**
3. أعد النشر

### ⚠️ الخطة المجانية
بتنام بعد 15 دقيقة خمول. النوم بيوقف:
- **المُصالح** → طلب عالق بيضل عالق
- **ويبهوك كريبتوموس** → دفعة بتوصل وما تنشحن

إما Starter، أو cron خارجي من [cron-job.org](https://cron-job.org) بينده `/health` كل 5 دقايق.

## المرحلة 6 — الإعداد الأول

`/start` → **⚙️ لوحة التحكم**:

| # | افعل | ليش |
|---|------|-----|
| 1 | 🔄 **مزامنة الآن** | بيسحب الكتالوج ويعرض رصيدك عند GGSoma |
| 2 | 💵 **التسعير** → الهامش العام | افتراضي 25% |
| 3 | 💵 **التسعير** → أقل هامش مسموح | افتراضي 5% — تحته بيوقف البيع |
| 4 | 💳 **الدفع** | فعّل الطرق — شوف [PAYMENTS.md](PAYMENTS.md) |
| 5 | 📝 **النصوص** → معرّف Binance Pay | بدونه زر بايننس ما بيظهر |
| 6 | ⚙️ **النظام** → يوزر الدعم | بيظهر كزر بشاشة المساعدة |
| 7 | 📦 **المنتجات** | أخفِ اللي ما بدك تبيعه |

### ⚠️ الهامش لازم يكون أكبر من أعلى خصم مستوى
الحارس بيحسب أوطى سعر ممكن يدفعه زبون **بعد أعلى خصم**. المستوى الماسي خصمه 5%.

لو حطّيت الهامش العام 5% وأقل هامش مسموح 5% → **كل المنتجات بتنوقف فوراً**. خلّي الهامش أعلى من (أقل هامش + أعلى خصم) بمسافة مريحة.

### الأوصاف بدها وقت
التفاصيل بتنسحب **15 منتج كل مزامنة** حتى ما نتجاوز حد GGSoma. كتالوج 100 منتج بدّو ~70 دقيقة ليكتمل أول مرة. عادي.

## المرحلة 7 — الاختبار قبل الزبائن

نفّذ كل بند وتأكد من النتيجة:

### الشراء
- [ ] اشترِ منتج حقيقي — **التسليم لازم يوصل**
- [ ] اشترِ ورصيدك ناقص سنت — «ناقصك 0.01$» مع زر شحن
- [ ] اضغط زر الشراء 5 مرات بسرعة — **ما لازم يطلع أي خطأ**
- [ ] اقفل النت بنص الشراء — «قيد التنفيذ» **مو رسالة خطأ**

### الدفع
- [ ] Stars بـ 50 نجمة → الرصيد يزيد 0.45$ فوراً
- [ ] Cryptomus بـ 1$ → الرصيد يزيد **بدون تدخّل منك**
- [ ] Binance Pay → توصلك بطاقة الموافقة
- [ ] **اضغط زر الموافقة مرتين** → لازم يقول «انشحنت من قبل»

> البند الأخير هو الأهم. لو شحن مرتين، **أوقف كل شي** وأعد تشغيل `02_functions.sql`.

### الحارس
- [ ] حط سعر يدوي أقل من التكلفة على منتج → المزامنة الجاية لازم توقفه وتنبّهك
- [ ] رجّع السعر → لازم يستأنف تلقائياً

### الـ logs
افتح **Logs** على Render وراقب أول ساعة. دوّر على:
```
[cryptomus] توقيع غير صالح     ← المفتاح غلط، ولا دفعة رح تنشحن
[kb] callback_data تجاوز 64    ← زر ميت
[sync] / [recon] / [alerts]    ← طبيعية
```

## حل المشاكل

| العَرَض | السبب الأرجح | الحل |
|---------|--------------|------|
| البوت ما بيرد | `WEBHOOK_URL` فيه `/` بالآخر | شيله وأعد النشر |
| دفعات كريبتوموس ما بتنشحن | التوقيع فاشل | راجع `CRYPTOMUS_API_KEY` وشوف الـ logs |
| الأزرار ما بتشتغل | الرسالة قديمة | `/menu` بيفتح رسالة جديدة |
| كل المنتجات موقوفة | الهامش أقل من الحد | ارفع الهامش أو نزّل «أقل هامش مسموح» |
| الأوصاف فاضية | المزامنة لسّه ماشية | استنى دورتين تلاتة |
| طلبات عالقة كتير | الخدمة بتنام | خطة Starter أو cron خارجي |
| «رصيد غير كافٍ» وأنت شاحن | رصيد **GGSoma** فاضي مو رصيد الزبون | `/wallet` أو ⚙️ → مزامنة |

## الأمان

- `SUPABASE_SERVICE_KEY` و `GG_API_KEY` و `CRYPTOMUS_API_KEY` — **سيرفر فقط، ولا تشاركهن أبداً**
- فعّل **Row Level Security** على جدول `orders` — فيه بيانات حسابات حقيقية بعمود `delivery`
- غيّر `WEBHOOK_SECRET` لو تسرّب — وحدّث رابط الويبهوك عند كريبتوموس معه
- راجع `ADMIN_IDS` — أي رقم هون عنده تحكم كامل بالأسعار والأرصدة
